## Checked and found sound (coverage note for the orchestrator)

- **Cue content cannot reach the new verbs.** `CUE_ACTIONS` excludes `service:*` and does not contain
  `preflight:run`; `executeCommand` refuses any non-`gm` source outside that vocabulary with
  `Object.hasOwn` (no prototype-chain escape), and both cue dispatch sites pass `source: 'cue'`.
  (`backend/src/gameRules/cueValidation.js:91–116`; `commandExecutor.js:121–128`;
  `cueEngineService.js:568–572`; `cue/timelineRuntime.js:243–247`.)
- **`session:start` is out of reach of a cue and of a non-operator.** `session:` maps to
  `session-lifecycle`, which is minted only at tier `operator`; `system:reset`'s executor bypass has its
  own explicit floor check in `adminEvents`. (`grants.js:46–55`, `:62`; `adminEvents.js:53–62`.)
- **The three new `service:*` verbs inherit the right floor automatically** via the `service:` prefix
  already mapped to `show-control` after the B0 close review — no per-action entry is needed, and adding
  one after the prefix entry would be dead code (first match wins). (`grants.js:74–78`, `:91–97`.)
- **The floor map has a structural completeness pin.** `oneAuthProofs.test.js:145` fails when a
  contracted action is unmapped; this is why SEC-02 is a specification gap rather than a silent hole. Its
  `RULED_NON_FLOOR` escape hatch is the risk, not the check.
- **Display-class identity is already taken from the verified token**, so an observe socket cannot flap a
  real GM station's device tracking by asserting its deviceId, and the `SCOREBOARD_` collision carve-out
  does not weaken that. (`socketServer.js:82–124`; `gmAuth.js:53–61`.)
- **`HealthRenderer` escapes every interpolated value** (`escapeHtml` on id, name, status, message), so
  the new operator-supplied `message` is not an XSS path on the GM dashboard — which is precisely why
  SEC-12 is about length/normalization and log integrity, not markup.
  (`ALNScanner/src/ui/renderers/HealthRenderer.js:1`, `:85–90`, `:142–159`.)
- **`sync:full` construction is cheap**: `buildEnvironmentState` reads cached `getState()` with no
  subprocess spawns, so an ungated `sync:request` is not a shell-out amplifier. (An earlier read of the
  contract test's comment suggested otherwise; the code disagrees and the code wins.)
  (`backend/src/websocket/environmentHelpers.js:30–68`.)
- **The E2E path seams the plan depends on already exist**: `E2E_PACK_PATH` and `E2E_PROFILE_PATH` are
  plumbed through the test server and session env with caller-wins precedence, so T1b's third Tier L leg
  and T5's divergent-pack flow are feasible as written.
  (`backend/tests/e2e/setup/test-server.js:122–150`; `tests/e2e/setup/session-env.js:129`;
  `package.json:40`.)
- **`PACK_PATH` / `PROFILE_PATH` are consistent precedents** for the `HOST_CONFIG_PATH` seam shape
  (`path.resolve` of the env value, one loud warn, no containment check) — env is trusted in this tree, so
  the seam itself is not a finding; SEC-05/SEC-06 are about validation and tracking, not the seam.
  (`packService.js:166–178`; `profileService.js:47–60`.)

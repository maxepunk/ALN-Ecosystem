## What changes most

- **Promises page, capability numbers**: 54 sentences drop "(capability N)"; where the capability's name is itself jargon (interaction primitives, the truth sweep, the session-bundle emitter) a short description replaces it.
- **Design flaws page, card internals**: 117 rows in the cause cards (diagram boxes, problem lines, design terms). Two renderer changes do the most: F7 drops the finding ids from all 92 problem lines, F6 turns blue's fix codes into a count.
- **Step, phase and "the map"**: about 40 sentences each. Step 3 becomes the design rounds, phase 1 the planning half, the map the candidate shape.
- **Engine words**: snapshot, push, builder, shape, envelope, stamp, fake, proof, adopt, preview and "its own names" account for most of the rest, each now one plain wording site-wide.

## How to apply

- Find each sentence by its source; the "Now" column quotes it, with "..." where the reader elided an unchanged part. Keep any `[[...]]` marker the sentence carries unless the row rewrites it.
- A card's "Today" line on Parts is the first sentence containing "today" in `mechanisms[i].plain` (SJ): a rewrite keeps "Today " at its start. Alternative titles keep the starts `ALT_TITLE_START` checks (A106, A108, A116).
- Keep the anchor id `step-3` (build checks at `build_site.py` 1829 and 1835); only its visible heading changes (D44).
- Renderer changes in `build_site.py`: F6 (`chips()`, line 109), F7 (`card_html()`, line 845), P21 to P30 (`promise_html` `qtext`, line 1410: a table of the nine question names), A9 (`MOMENTS_KEY`). Parity cells go through `PARITY_WORDS`, which replaces a whole cell, so each entry restates the full cell (rows 12 and 14 already have entries: extend them).
- `2026-10-31-engine-jobs.md` holds the same sentences as its JSON; the page reads only the JSON.
- Not touched: card code-file lists (engineers' reference), the flaw titles, the part names (Joins and proofs, Engine instance keep their words), quoted earlier wordings on Changes, and the anchor ids.

### 1.2 How the standalone tablet gets the game, and what a change does

**The app shell.** A standalone tablet is served from a static origin, GitHub Pages in the ALN setup (`ALNScanner/CLAUDE.md`, Deployment), or from the engine at `/gm-scanner/` if the GM taps "Standalone" there. The service worker has no precache list; it caches each file the first time it is fetched and serves network-first, falling back to the cache only when the fetch fails (`ALNScanner/sw.js:3-7,53-65`). A tablet that was never opened online has nothing to fall back to (inference from `sw.js:3-7`; not run).

**The pack (the rules, token list, wording and colours).** The channel is chosen by where the page is served from, not by the GM's choice of mode (`core/packLoader.js:19-21,109-120`). From Pages, the pack is the static files at `./` (`pack-manifest.json` and the files it lists); from `/gm-scanner/`, it is `/api/pack/*`. The Pages copy is the ALN-TokenData submodule published beside the app (`vite.config.js:28`, `publicDir: 'data'`; the design record `2026-07-09-phase3-1-standalone-pack-loading.md` section 1). So a pack update reaches a standalone tablet only after someone publishes to Pages by hand (`sync.py --deploy`, C15) and the tablet then starts the app while online.

The load runs once, at app start (`app/app.js:123` calls `initializationSteps.js:148-149`, then `core/tokenManager.js:50-103`, then `core/packLoader.js:130-182`):

1. Network tier. Fetch the manifest with `no-store` and an 8 second limit (`:46,136`). If its hash equals the saved pointer and the cached copy is complete, use the cache (`:144-162`). If it differs, fetch the four rules files (game, tokens, strings, theme: `:63`) into a staging cache, check each file's sha1, check that the token list is usable and that declared sidecars arrived, then change the pointer in one write and delete the other pack caches (`:210-286`). Any failure discards the staging cache and leaves the active pack alone.
2. Cache tier: the last activated pack (`:171-177`).
3. Bundled tier: the copy built into the app at build time, with a warning badge on screen (`:180`, `:353-389`; `index.html:79`).

The tablet then replaces its scoring tables, group multipliers, mode table, strings and colours in place (`tokenManager.js:50-103`; `core/scoring.js:64-97,139-142`; `core/modeSemantics.js:84-92`). It shows `pack <version> (<hash>) · <source>` and the "bundled" badge (`initializationSteps.js:242-266`). In standalone that line is the only way to compare two tablets (the design record, sections 4 and 6).

**What a pack change does.**

- Nothing happens to a running game. No code watches for a newer pack after start (`core/packLoader.js:23-26`; the only caller is `app.js:123`).
- A reload mid-game, while online, adopts the new pack under the old game. The reload restores the saved game (`app/app.js:455-468`, `preserveSession: true`) and the network tier runs before it (`initializationSteps.js:148`). The design record promised "never mid-session" (section 3); the code enforces only "at app start" (SG-03).
- The saved game carries no pack identity (`LocalStorage.js:31-37,164-172`). The backend stamps the pack on every game it creates and compares at restore (`backend/src/services/sessionService.js:212-216`).
- After adoption: stored transactions keep the points they were scored with, but Team Details recalculates every token card from the new table (`ui/renderers/GameOpsRenderer.js:299`), and a delete rebuilds bonuses with the new multipliers (`LocalStorage.js:503-516`, `core/scoring.js:144-162`). A mode the new pack does not declare is reset to the pack's first mode at start, with a log line (`initializationSteps.js:279-296`).
- The standalone tablet applies none of the engine's checks on a pack. The backend refuses a pack whose `requires` list names a capability it lacks and one whose `engine.minVersion` it does not meet (`backend/src/services/packService.js:728-735,762-763`). The tablet reads neither field (`grep -rn "minVersion\|requires" ALNScanner/src` finds no reader). It has three client defences: an exact schema-version check (`tokenManager.js:50-71`), a loud warning for undeclared group names (`:118-138`), and mode-field normalization (`modeSemantics.js:115-137`). Whether the Pages publishing path runs the engine's own gate is not verified. `config-tool/lib/publish.js:19-22` runs it when publishing to a live pack folder; how that folder reaches Pages is outside what I read (SG-08).

### 1.3 What a standalone game needs that today's standalone mode lacks or gets wrong

Section 2 holds every item with its citation. In plain terms, a whole game with no engine needs the following.

1. **A way to start a named game, a second game, and a real pause.** Today the tablet opens into an unnamed "Active" game, Pause fails with "No active session to pause", and the only "Create New Session" button can never draw (SG-01, A-13 / C-42).
2. **A scan gate that refuses when the game is paused, not started or ended.** Today a scan into a paused game shows "Transaction Complete!", records nothing and locks the token; a scan into an ended game is recorded (A-02 / C-09).
3. **A finished game that survives.** Today the only way to start over is Reset All Scores, which deletes every transaction. No report can be downloaded and nothing exports (SG-02, SG-04, A-37).
4. **A record of which pack scored the game, and no silent pack swap mid-game** (SG-03).
5. **The same rules as the backend, from one source.** Today every rule is a hand-kept second copy, and some of the rules are outside the backend's `gameRules` (SG-11, C-10, A-36 / C-11).
6. **Screens that tell the truth.** Team Details shows base score only and $0 bonus while the scoreboard counts the bonus (A-03 / A-04 / C-06); every row of Game Activity reads "Unknown, $0" (A-07 / C-15); the History badge stays hidden after a reload (A-22).
7. **A stated answer for what exposure does with no TV, and for the game clock.** Detective-style evidence has no public surface; the pack's game clock has no reader (SG-07, SG-10).
8. **A declaration that the game is standalone, and a refusal to mix.** Nothing declares it today; each tablet's first tap decides (SG-05). A second standalone tablet is a separate game (SG-06).
9. **A readiness verdict for the tablet** (app cached, pack current, storage working), because there is no engine pre-show check to give one (SG-09).

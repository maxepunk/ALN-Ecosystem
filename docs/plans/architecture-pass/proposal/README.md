# The architecture proposal (2026-11-10)

`index.html` is the proposal the owner reads, published in place of the
old site at https://claude.ai/artifact/RzL2FzCZ4eESSNMYwkkKPL. It is
the single source: there is no second copy of its text. Each
improvement's "Where this is in the code" list holds its evidence.

How it was made, following the skill `improve-codebase-architecture`:

1. The agent read what the engine is supposed to be
   (`../rework/2026-11-10-what-the-engine-is.md`) and the code maps of
   2026-11-01 (`../2026-11-01-engine-shape.md`, `../relationships/`),
   and checked the claims it used in the code itself.
2. It wrote a first draft of seven improvements (in git history at
   `1bae2452`: `2026-11-10-proposal-draft.md` and the first
   `index.html`).
3. Three independent readers challenged the draft with the code in
   front of them: `challenge/1-code-truth.md`,
   `challenge/2-purpose-fit.md`, `challenge/3-alternatives.md`. The
   agent checked every line they cited before using it.
4. The agent rewrote the proposal.

What the challenge changed:

- Thirteen "today" claims were corrected. Among them: requests come in
  six ways, not three; sixteen repeated decisions, not eighteen; five
  hand-kept lists of steps, not two; the profile does declare a kit
  with no show machine, though no device reads it; build-time contract
  tests exist; the hardware scanner runs no game rules.
- The first draft's improvements 1 (facts) and 4 (door) became one:
  one way in, one record, one way out. Its improvement 2 (rules)
  became "the same core runs wherever a game is decided", because the
  tablet's second engine mirrors the record, not the rule functions.
- The record as an ordered list of everything decided became the
  recommended choice inside improvement 1.
- The life-of-a-game table widened to "every fact has a stated life: a
  session, an install or a production".
- "Marked places where new rules, new gear and new screens plug in"
  was added, as worth exploring.
- "Each copy keeps to itself" gained "built in one place", and its
  cost was corrected: it is not small.
- Stand-ins are the ratified kind (an ordinary profile pointing the
  real programs at stand-in gear), not fake drivers.
- Who keeps the programs running became a choice inside improvement 4,
  with a one-day trial on the new show machine.
- The order changed: the room's side first; the core worked through
  with the owner meanwhile, then built as a thin slice on both hosts
  with the second game's taps as test cases.
- Costs are stated on every card.

Left out on purpose, and why:

- Making code from the protocol's definition: checks and a version
  first; generation where it pays.
- Rule tables for the hardware scanner: it runs no rules. Its replies
  carry what to show.
- A kit with player scanners only has nothing that gathers a record.
  That is true today and is a choice for later.
- The pack filtered for each reader, and a game as one installable
  thing with its media, are named under improvements 1 and 5 and not
  designed here.

Three owner questions the proposal does not decide: what a GM may tell
a team while a tablet is cut off; what a device that missed an update
may do; where a rehearsal copy may run while a session is live.
